# 第一部分 · 研究计划

## 项目定位

以**技法与成文规范**为唯一切口，追问西方绘画的「公认原则」从哪里来、如何被强制执行、又在什么条件下松动，最终汇向 1860–1906 年。时间跨度约 1390–1906，主线为意大利—荷兰—西班牙—法国。定位为塞尚绘画逻辑研究的前传。

**为什么锁定技法层而非通史**

- **只有技法层是可核查的。** 颜料分析、X 光／红外／元素分布图、画论原文均有第一手出处；做「现代主义兴起」通论则不可避免大量转述二手文献。
- **「公认原则」在技法层是写下来的。** Cennini（约 1390）、Alberti《论绘画》（1435）、Leonardo、法兰西学院教条、Chevreul（1839）、Charles Blanc（1867）——「公认」可以指着页码说，不必靠断言。
- **范围可收口。** 五套系统 × 各约 6 个节点 = 有限工作量；「现代主义兴起」没有天然边界。

纯技法解释不了「为什么这些规则有约束力」，故另设一章制度史。整体对比回顾以「对照实验室」形式保留：不另写通史，而是每套系统给一组跨四百年的并列图版。

## 通用规范

- **四类可信度标记**：公论 / 学者观点（署名署年 + 方法论）/ 本文推断 / 史料提示
- **来源优先级**：馆藏官方藏品页 > 机构技术公报 > 学者专著论文 > 展览图录 > 教学性百科
- 画论引用须给**版本与页码**，并区分原文与后人转述
- 图版附馆藏页、文件页、原图直链、分辨率；细节裁切须标注**原图坐标**以便回溯
- 面向零绘画经验读者：每个技术概念先给一句话功能定义，再展开

## 每章七段式模板（第 2–5 章统一使用）

1. **这套系统要解决什么问题** — 一句话，零基础可读
2. **规则是怎么被写下来的** — 原文摘引 + 版本页码，区分原文与后人转述
3. **操作步骤拆解** — 分层示意：底子 → 素描稿 → 底色层 → 塑形 → 罩染 → 提亮，逐层可切换显示
4. **范例逐幅精读** — 全图 → 3–6 张标注细节裁切 → 「你在看什么」逐条说明 → 机构技术影像（X 光／红外／元素分布图）凡公开者附上
5. **什么时候开始失效** — 这套规则在什么条件下撑不住了
6. **众声** — 不同学者对同一处细节的不同读法，署名署年、标明方法论
7. **延伸材料** — 4–6 项，分入门 / 进阶 / 原始文献 / 可看的技术检测四档，注明为什么读它、难度、获取方式

### 范例与细节焦点

| 作品 | 细节看什么 |
| --- | --- |
| 14 世纪蛋彩板 | Cennini 系统实拍：可见的排线塑形，暗部为纯色 |
| 达·芬奇《岩间圣母》（伦敦） | sfumato：手背与下颌过渡处几乎无笔痕；配红外与断层分析 |
| 提香 | 依 NG 技术公报第 34 卷（提香 1540 年前技法专号）逐层拆解 |
| 卡拉瓦乔《以马忤斯的晚餐》 | 单光源、暗底、无中间调；手部边缘由亮直落黑 |
| 伦勃朗《夜巡》 | 用 717 亿像素图做极限放大：铠甲高光的堆塑、暗部的透明褐层；配元素分布图 |

**互动**：同一局部的「明暗读法 ↔ 冷暖读法」双通道切换（去色 vs 色温映射）

## 第 4 章　色彩与材料：调色板决定了什么可以被画出来

**技法要点**：颜料的物理限制 · 固有色体系 · 罩染的透明色 vs 覆盖色 · 合成颜料年表 · 光学混色 · 补色与「同时对比」· 简化调色板的后果

**年表锚点**：普鲁士蓝 1704 · 钴蓝 1802 · 镉 1817 · 人造群青 1826（法国政府悬赏）· 锡管颜料 1841 · 茜素合成 1868

### 范例与细节焦点

| 作品 | 细节看什么 |
| --- | --- |
| 凡·艾克 | 天然群青的价格与位置：为什么最贵的蓝只给圣母的袍子 |

| 透纳 | 铬黄的冒险与变色 |

| 梵高《阿尔勒的卧室》 | 芝加哥艺术学院用 macro-XRF 复原原始颜色，证明墙面原为紫色而非蓝色——全报告最有说服力的「材料改变了我们看到的历史」案例 |

### 延伸材料

- **《同时对比律》**（Michel Eugène Chevreul, 1839）— 十九世纪色彩理论的源头；重点在其**接受史**：画家多半只看图版不读正文，因而系统性误读。难度：★★★★☆。获取：法文原版免费

# 第二部分 · 输出格式与托管规范

## A. 总体形态

**一个静态站点，单页长读（single long-form page）+ 若干独立子页。** 不使用 React/Next 等框架，避免构建复杂度与体积。

技术栈：

- 内容源：Markdown（每章一个 `.md` 文件）
- 构建：Python 脚本把 Markdown 编译成一个 `index.html`
- 前端：原生 HTML + CSS + 一个 `app.js`（无打包器、无 npm 依赖）
- 依赖：Python `markdown`（启用 `extra`、`sane_lists` 扩展）、`Pillow`

**为什么单页**：技法内容需要频繁前后互相参照（第 5 章的笔触要回看第 3 章的明暗细节），单页 + 锚点跳转 + 侧边固定目录远优于多页跳转。子页只留三个：术语表、图版索引、阅读路线图。


## D. 细节裁切规范（本项目核心技术点）

`images/crops.json`：

```json
{
  "masaccio-trinity-coffers": {
    "source": "masaccio-trinity",
    "box": [1240, 180, 900, 640],
    "note": "藻井方格收缩序列",
    "annotations": [
      {"type": "box",   "rect": [120, 90, 180, 130], "label": "第一格"},
      {"type": "arrow", "from": [300, 200], "to": [520, 260], "label": "正交线走向"},
      {"type": "line",  "points": [[0, 310], [900, 310]], "label": "视平线"}
    ]
  }
}
```

- `box` 为**原图像素坐标** `[x, y, w, h]`，必须写进 `sources.csv`，让读者能回馆藏页自行核对
- 裁切后**不缩小**；若短边不足 1200px 则用 Lanczos 上采样至 1200px，保证细节可读
- 标注由 Pillow 绘制：描边宽度随图尺寸缩放，标注文字用带半透明底的白字，颜色统一取 `#b0522c`
- 每张裁切额外输出一张**无标注版**，前端提供「隐藏标注」开关（先自己看，再看解读）
- 设 `Image.MAX_IMAGE_PIXELS = None`，因 gigapixel 图会触发 Pillow 的解压炸弹保护

`类型` 取值：`全图` / `细节裁切` / `技术影像` / `示意图`。细节裁切行必须填 `裁切坐标` 与 `母图编号`。

## F. 图像文件与 Git

原图总量可能达数百 MB（gigapixel 局部下载尤其大）。三种方案按需选：

1. **推荐**：`images/originals/` 写进 `.gitignore`，仓库只提交 `_manifest.json` + 下载脚本 `fetch_images.py`，任何人可按清单重新拉取。派生图（`site/img/`）体积可控，正常提交。
2. Git LFS 托管原图（注意 GitHub 免费额度 1GB 存储 / 1GB 月流量）。
3. 原图放外部对象存储，manifest 里记 URL。

## G. 设计系统

```css
--paper:      #f7f3ea;   /* 底色 */
--ink:        #221f1b;   /* 正文 */
--terracotta: #b0522c;   /* 强调、图上标注 */
--blue:       #3e5f80;   /* 学者观点标记 */
--olive:      #6d7a4e;   /* 公论标记 */
--measure:    42rem;     /* 正文行宽 */
```

- 字体：正文 Noto Serif SC，拉丁斜体 Instrument Serif，界面与标签 Noto Sans SC
- 深色模式：`[data-theme="dark"]` 属性切换，全部颜色走 CSS 变量
- 外层容器最大宽度 1140px；侧栏目录 `position: sticky` 且 `max-height: calc(100vh - 7rem); overflow-y: auto`
- 所有表格包在 `.table-scroll { overflow-x: auto }` 里，防止移动端横向溢出
- 移动端断点检查 375px，不得出现横向滚动

## H. 交互组件清单（`app.js`，全部原生实现）

| 组件 | 行为 |
| --- | --- |
| 细节放大镜 | 点击全图任意位置，弹层显示该处 2× 局部（用 2000px 派生图，CSS `transform: scale` + `transform-origin`） |
| 标注开关 | 在有标注／无标注两版裁切图之间切换 |
| 透视网格叠加 | 绝对定位一层 SVG，画灭点、正交线、视平线；开关控制 `opacity` |
| 明暗↔冷暖切换 | 同一局部三通道：原图 / CSS `filter: grayscale(1)` / 预生成的色温映射图 |
| 对比滑块 | 两图叠放，`clip-path: inset()` 随拖动改变 |
| 调色板年表 | 拖动年份滑块，点亮当年可用颜料色块 |
| 分层剖面 | 多层 `<img>` 叠放，勾选框逐层显隐 |
| 侧边目录 | `IntersectionObserver` 高亮当前章节 |

**重要限制**：不要使用 `localStorage` / `sessionStorage` / `indexedDB`（若日后发布到沙箱托管环境会被拦截）。主题偏好等临时状态用内存变量或 `window.name` 存放。

## I. 托管方案

仓库设为 **private**。静态站点托管按隐私需求选：

| 方案 | 私密性 | 说明 |
| --- | --- | --- |
| **Cloudflare Pages + Access** | 强，可按邮箱白名单 | 免费额度足够，推荐 |
| **Vercel**（Hobby） | 可开 Password Protection（付费）或 Preview 部署仅登录可见 | 与 GitHub 私有仓库直连，push 即部署 |
| **Netlify** | 站点级密码保护（付费） | 同上 |
| **GitHub Pages** | 私有仓库的 Pages 需 GitHub Pro / Enterprise | 免费版从私有仓库发布会变成公开站点，注意 |
| **纯本地** | 最强 | 于 `site/` 目录运行 `python -m http.server` 即可，无需部署 |

无论哪种，构建产物都提交到仓库（`site/index.html` 等），使托管平台无需运行 Python。CI 可选：GitHub Actions 在 push 时跑 `build_assets.py && build_site.py` 并校验图版完整性。
